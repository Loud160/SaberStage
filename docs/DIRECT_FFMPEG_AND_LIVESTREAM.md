# Direct FFmpeg hardware recording and live streaming

## User-facing behavior

The center menu's `General` tab switches between separate local-recording and livestream profiles. Resolution, frame rate, target/peak bitrate, rate control, hardware tuning, H.264 profile/level, keyframe interval, and AAC bitrate update to show the selected profile, so local quality does not have to match broadcast quality. Resolution, frame rate, and target bitrate share the first Video Output row; the remaining encoder controls stay in that same section. The right-side menu retains the operational `Record`, `Live Stream`, and `Files` views. Every interactive control has an average-user hover explanation.

Local recording and live streaming both use SaberStage's private Direct FFmpeg runtime and Android MediaCodec surface encoder. SaberStage never starts a software H.264 encoder. The build and package do not depend on Hollywood. 1440p and aggressive profile/level combinations remain capability-dependent and fail safely when MediaCodec rejects them.

`Go Live` starts every enabled destination through one shared hardware H.264 encoder. Twitch, Kick, YouTube, and Custom each retain an independent master switch, server-address/key pair, and session-only overrides in their own center-menu tab. Paste actions never log clipboard contents; changing a built-in server address requires acknowledging a warning. The `Set` button for either field offers `Cancel`, `Use Once`, and `Save in Settings`: session values disappear when Beat Saber closes, while saving is an explicit local plaintext persistence choice. Before creating any sink, SaberStage validates all enabled destinations against their provider format and bitrate limits, verifies their required fields, and checks aggregate video-plus-audio traffic against 70 percent of the last saved sustained-upload measurement. Any failure blocks the entire start and identifies the setting that must be corrected. If local recording is idle, going live starts a stream-only camera/audio capture: no H.264, WAV, partial MP4, or completed MP4 file is created. `Stop Stream` tears down that stream-only capture completely. If the user explicitly started a compatible local recording before going live, all destinations share that existing hardware encode and `Stop Stream` leaves the intentional local recording running.

The Live Stream tab provides separate `Game Sound` and `Quest Microphone` switches, each with its own 0-200% volume slider. Defaults are game sound on at 100% and microphone off at 100%. These controls change only the AAC mix sent to the live service: the player-facing game volume and local recording PCM are unchanged. Source-enable switches remain locked while live because they own capture resources, while both gain sliders update the active mixer immediately under its existing stream mutex. Microphone input uses a bounded, callback-safe AAudio ring and requires Android microphone permission. SaberStage requests the runtime permission when it was declared during patching; if Beat Saber lacks the declaration entirely, it identifies that condition and directs the user to enable MBF's `Microphone Access` option and repatch the game. Mic underflow produces silence instead of blocking gameplay or the stream.

The default-on `Keep Headset Awake` option applies two stream-scoped guards: Unity's Android sleep timeout is set to `NeverSleep`, and SaberStage's Android bridge applies the activity's keep-screen-on flag while requesting the normal Horizon OS proximity-sleep override. The exact previous Unity timeout and normal proximity behavior are restored when the stream stops or fails. The switch is locked during a live session so protection cannot be removed halfway through a broadcast. Quest firmware can still force suspension for shutdown, thermal, battery, or operating-system safety conditions.

The floating controls select either Record or Stream and provide `START`, `PAUSE`, and `STOP` plus five-second and session-total drop counters. Stream mode also exposes blue game-sound and microphone buttons. Their embedded PNG icons show active, muted, and unavailable states without relying on a font or hand-built shape, and both buttons apply only a session mute so the configured enable switches and volumes remain intact. Streaming pause keeps the RTMP session alive, replaces the camera with the selected PNG/JPEG/GIF (or SaberStage's embedded `Taking A Break` image), sends timed silence, and locks the audio buttons. Resume restores the live spectator camera and audio mix. AFK substitution cannot be used while a Direct FFmpeg local file is sharing the stream encode because it would put the AFK screen into that recording too.

Twitch, Kick, YouTube, and Custom RTMP/RTMPS destinations are supported as independent outputs. An exhausted reconnect or other runtime failure disables only that destination; other providers and the shared encoder continue. A provider-failure dialog is deferred while a map is active and shown when the player returns to a menu, so error reporting cannot interrupt gameplay.

Optional Twitch device authorization through SaberStage's embedded public application ID allows the mod to apply a saved stream title immediately before going live, update that title through Helix without ending an active stream, display bounded Twitch chat on a movable HMD-only panel, and optionally post one current-map summary from the streamer's own account when gameplay begins. The summary contains locally verified song, artist, difficulty, mapper, `m:ss` duration, NPS, and declared Chroma/Noodle/Vivify metadata; unavailable values such as a missing star-rating provider are omitted. Posting is disabled by default and only occurs while a Twitch stream is active. The user approves the device code through Twitch rather than entering a Twitch password in Beat Saber. Existing account links must be reconnected once to grant Twitch's `user:write:chat` scope. SaberStage refreshes expiring access tokens on a single background worker, persists Twitch's rotated refresh token, restarts only the chat connection when credentials rotate, and retries transient refresh failures with bounded backoff. Map inspection and posting are background work and cannot hold up gameplay startup. A revoked or permanently invalid authorization still requires the user to connect again.

The hardware encoder emits Annex-B H.264. SaberStage fans the same headers and access units to each provider sink, whose FFmpeg FLV muxer generates its own complete AVC sequence header and length-prefixed RTMP packets. This deliberately avoids a second, partial AVCC implementation in SaberStage and keeps High-profile stream headers on FFmpeg's established conversion path. AAC encoder priming is also applied to each sink's input timestamp origin so its first packet cannot acquire a negative DTS after the FLV video timeline has begun at zero. Stream diagnostics record only provider identity, media parameters, sanitized state transitions, and packet/byte counters; joined endpoints and stream keys are never logged.

The current Direct input-surface bridge is an OpenGL ES/EGL implementation. It verifies that Unity has a current EGL display/context and that the context config advertises `EGL_RECORDABLE_ANDROID` before it uses the native texture as a GL texture. If Unity is running Vulkan or any bridge stage cannot present frames, capture stops with a stage-specific diagnostic instead of silently accepting an empty stream or starting a CPU fallback.

## Local recording timeline and A/V synchronization

SaberStage's private FFmpeg finalizer preserves each frame's scheduled monotonic presentation time instead of renumbering whatever frames MediaCodec happens to return as a gap-free sequence. If the spectator path misses a presentation deadline, the MP4 therefore preserves elapsed video time rather than silently shortening the picture track relative to continuously sampled audio. Pause/resume segments are normalized onto one continuous presentation timeline.

The first submitted video frame and first nonempty Unity audio callback are measured against the same monotonic clock. A later audio start receives a matching positive PTS offset; an earlier audio start has only the leading samples before video trimmed. Finalization stops audio at the video timeline plus at most one AAC frame, preventing capture-shutdown audio from extending the file. The stop log records first-video time, first-audio time, and the applied offset in milliseconds so a device report can distinguish capture-start skew from long-session drift. This is compile- and host-validated, but recorded Quest clips still need explicit lip/saber-impact sync checks before the behavior is considered device-proven.

## Performance isolation

- The Unity audio callback performs only a bounded copy into a preallocated SPSC ring.
- WAV writes, PCM conversion, and live audio fan-out run on an audio worker.
- Encoded H.264 file writes run on a bounded writer worker, not an encoder callback.
- Each destination's network writes and AAC encoding run on its own livestream worker.
- The EGL bridge restores Unity's render context on every setup failure and tears its MediaCodec surface down only after the encoder worker has drained.
- Direct diagnostics separately count scheduled camera frames, render events, EGL setup attempts, successful surface presents, encoder submissions, output packets/bytes, `EAGAIN` retries, bounded-queue drops, and EGL/GL failure codes. The controller logs the snapshot both at failure and at segment shutdown.
- FFmpeg `EAGAIN` back-pressure drains output and retries the same surface frame instead of discarding that frame's timestamp.
- Video and audio network queues are bounded; overload drops broadcast packets before blocking gameplay or local capture.
- The preview capture-exclusion renderer lists are rebuilt only when panels are attached, created, or removed—not for every spectator frame.
- A 90-frame refresh cadence replaces per-frame global AudioListener enumeration; the capture listener still follows the HMD pose each frame.
- Optional 2x/4x camera MSAA renders the third-person camera into a private multisampled target and resolves once into the backend's single-sample encoder texture. It does not change Beat Saber's headset MSAA; Off remains the conservative default.

These changes address identified structural stalls, but they do not establish a Quest performance result. Quest 2/3 testing must measure camera-only, Direct FFmpeg at 720p30 and 1080p30, representative heavy gameplay/mod scenes, and controlled test broadcasts. 1080p30 remains the conservative default; 60 FPS and 1440p require evidence before being recommended.

## Private runtime and licensing

`scripts/build-ffmpeg-hardware.ps1` invokes the reproducible WSL build. It downloads SHA-256-pinned FFmpeg 9.0.1 and Mbed TLS 3.6.7 sources, builds for Android API 29/ARM64, and stages only `libavformat`, `libavcodec`, and `libavutil` shared libraries. Enabled functionality is MediaCodec H.264, native AAC, H.264/WAV input, MP4/FLV output, and file/TCP/TLS/RTMP/RTMPS protocols. GPL, nonfree, and x264 features are machine-checked off. Mbed TLS 3 requires FFmpeg's LGPLv3 configuration.

The build also emits exact configuration, upstream licenses, source hashes, and the small SaberStage patch diff. FFmpeg receives a private `-saberstage9` SONAME suffix and `SABERSTAGE9` symbol version namespace so it cannot bind to another mod's unversioned FFmpeg runtime by accident.

## Security boundary

TLS certificate verification is enabled for RTMPS against Android's system trust directory. Stream keys are rejected when they contain whitespace/control characters, masked after entry, never written to ordinary logs, and removed from support-archive copies of `settings.json`. Twitch access and refresh tokens exist as plaintext only in owned process memory while Beat Saber is running. At rest they are encrypted with an AES-256-GCM key generated and held by Android Keystore; `settings.json` stores only the versioned authenticated ciphertext envelope. Schema-25 and older plaintext OAuth fields are read once for migration, immediately removed from disk, and replaced with the protected envelope. If Android invalidates or loses the key, SaberStage clears the unusable authorization and asks the user to reconnect instead of falling back to plaintext. Support archives redact both legacy token fields and the protected envelope. `Use Once` stream keys and runtime OAuth token buffers are cleared from owned memory on shutdown. Saved ingest stream keys remain an explicit local-settings choice and are separate from Keystore-protected Twitch account authorization. Clearing a key affects only the selected service.

## Device-validation boundary

The zero-byte Direct capture incident is now diagnosable and locally recoverable, but a true Vulkan-to-MediaCodec input-surface bridge remains future work. Before Direct mode or livestreaming is considered release-proven, device testing must establish:

- MediaCodec surface input, RGB orientation, color, and exact frame pacing;
- 720p30 and 1080p30 local Direct FFmpeg recording with desktop `ffprobe`/decode inspection;
- repeated Direct FFmpeg local-recording start, stop, pause, and recovery behavior;
- Twitch, Kick, YouTube, Custom, and simultaneous endpoint behavior using test channels;
- all-or-nothing provider configuration, format-cap, and aggregate-bandwidth preflight failures;
- isolated runtime failure of one destination while the remaining streams continue;
- FLV H.264 sequence headers/access units, AAC, A/V sync, stop/trailer handling, TLS certificates, and reconnect;
- queue depth, dropped-media telemetry, memory growth, thermals, and gameplay frame rate in representative heavy scenes;
- whether 1080p60 or 1440p modes are acceptable on each supported Quest generation.
