# Integrated avatar architecture

The avatar is a Stage 3 SaberStage subsystem, not a separate general-purpose mod. `AvatarManager` owns selected asset, load/unload, rig, IK/tracking binding, per-avatar scale/model-forward correction, calibration, visibility, and failure fallback. Camera and compositor see a generic subject anchor/render source; encoder and transports do not know an avatar exists. The manager now owns exactly one `VrmUnityRuntime`; unload unbinds the solver before destroying the hierarchy, meshes, materials, textures, and generated Avatar.

Tracking inputs are HMD and controllers initially, with optional supported body trackers later. The versioned [player calibration subsystem](PLAYER_CALIBRATION.md) persists semantic offsets, reach, motion envelopes, and movement signatures relative to the current player/tracking origin, never opaque scene-world coordinates. It remains separate from VRM bone/rest calibration so the same player profile can be combined with another avatar. Recenter rebases runtime anchors while preserving calibration. Manual `Recenter Avatar` and per-avatar/factory resets remain recovery tools.

Default visibility is full avatar in broadcast and hidden/minimal in HMD to avoid body occlusion. Assets are validated and budgeted before activation; failure removes only the avatar source. VRM Qavatars demonstrates Quest VRM feasibility but is only a [research reference](https://github.com/BSQ-VRM/VRM-Qavatars); SaberStage will not copy its loader, rig, or implementation.

## Implemented trackerless-solver boundary

The `AvatarManager` now accepts one Unity humanoid `Animator` from the VRM runtime. Binding maps and caches the humanoid transforms once, records their original local and world rest poses, measures the avatar skeleton, disables the Animator so it cannot overwrite solved bones, and restores the original local transforms and Animator state on unbind. The solver does not discover or load VRM assets itself. `Vrm0Parser` produces neutral C++ data without Unity types; `VrmUnityRuntime` is the only glTF-to-Unity adapter and passes only the completed Animator through this seam.

Per rendered pose, `PlayerTransforms` supplies the cached HMD and menu/controller transforms. During gameplay, `AvatarManager` discovers Beat Saber's active left/right `Saber` instances and samples each visible `_handleTransform` as the authoritative hand position/orientation source; controller transforms remain the menu fallback. `Update` writes one coherent fixed-size native `TrackingSample`. `LateUpdate` runs the native solver and issues one `SetPositionAndRotation` call per mapped/affected humanoid bone. The primary SaberStage camera has a pre-cull callback that resamples, solves, and writes immediately before its manually controlled render, including Hollywood recording renders. Sequence and Unity-frame stamps prevent the same input sample from being solved twice while still allowing a deliberately fresher pre-render sample.

The current native solver contains measured eye-height and arm-span calibration, explicit VRM head-to-eye mapping, a portable player profile with source-aware multi-pose grip/reach fitting, bounded shoulder assistance and five-percent maximum arm stretch, persistent grip-to-hand rotation offsets, stateful elbow poles, analytic two-bone arms and legs, a single-curvature spine chain (with a bounded constrained-FABRIK fallback), a personalized but still `LOCKED`/`TURNING`/`SETTLING` body-yaw estimator, an elliptical lean envelope and deterministic lean/translation confidence model, dimension-normalized pelvis/crouch estimation, persistent planted foot anchors, signature-informed one-foot-at-a-time translation/pivot steps, and conservative airborne recovery. Optional FBT overrides, terrain feet, continuous locomotion, and gait animation are intentionally absent.

The solver hot path uses fixed arrays and value types. Host tests instrument global allocation and verify zero heap allocations during a complete solve. Managed object discovery and humanoid binding occur outside the per-frame solve path.

## Avatar cutout quality controls

`Avatar Cutout Smoothing` is implemented inside SaberStage's embedded MToon shaders, so it applies consistently to the primary avatar, worn view, display clones, menu preview, and third-person recording without changing Beat Saber's global graphics. `Off` uses the authored hard alpha cutoff; `Low`, `Medium`, and `High` progressively widen a screen-space coverage transition and use a stable dither when the current target is not multisampled. Higher levels can add fragment-shader work on complex hair or clothing and are described that way in the menu tooltip.

`Alpha To Coverage` is a separate opt-in. It is enabled in the menu only after the loaded avatar reports at least one supported MToon alpha-cutout material. The material writes coverage only when the user enables the option; on a single-sample target it provides no MSAA benefit, while the third-person camera's optional 2x/4x target can use it directly. The setting is never presented as game-wide MSAA and does not take ownership of graphics options managed by another mod.
