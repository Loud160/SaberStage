# Logger Hardening and Repository Audit Plan

## Purpose

This pass removes SaberStage's direct runtime dependency on Paper2, adds a
private native diagnostic path that remains available when another mod installs
an incompatible Paper2 version, and hardens confirmed crash boundaries without
changing the mod's intended camera, recording, streaming, avatar, or menu
behavior.

The work starts from `Avatar-Framework` commit
`c8f785092cab8e3c27b8bbefd7bf23921b1cfe98` on the isolated
`logger-hardening-and-repo-audit` branch. Big Screen is reference-only.

## Boundaries

- Use Native Logger Quest as a private static implementation detail of
  `libsaberstage.so`.
- Remove only SaberStage's direct Paper2 dependency. QPM dependencies may
  continue to use Paper2 normally.
- Add catches at native, Unity, worker-thread, and teardown boundaries where a
  real exception can currently escape or terminate the game.
- Preserve expected user/content/network errors as recoverable operation
  failures. Do not count them as internal crashes or hide their useful detail.
- Keep all Unity object creation, mutation, and dialog presentation on the Unity
  main thread.
- Do not redesign feature behavior during this audit. Performance changes are
  limited to eliminating confirmed synchronous high-frequency persistence or
  blocking work where the existing behavior can be preserved.
- Keep local device backups and diagnostics outside version control.

## Stages

### Stage 1: Baseline and evidence

1. Record the exact branch base and dirty-tree state.
2. Run all host and repository invariant tests.
3. Produce a clean ARM64 build before edits.
4. Record only source-backed findings in the pre-change review.

### Stage 2: Private logger integration

1. Resolve the published Native Logger Quest source through an immutable
   revision and SHA-256-verified archive, with a verified offline cache.
2. Link the logger statically and enable its private Paper abort bridge.
3. Replace the Paper formatting façade without forcing widespread call-site
   changes.
4. Initialize logging before ordinary startup work and flush critical/shutdown
   records with bounded waits.
5. Remove Paper2 from SaberStage's direct QMOD dependency list.
6. Extend packaging/build validation to reject a direct Paper2 `DT_NEEDED`
   entry or exported Paper wrapper symbols.

### Stage 3: Error boundaries and user-visible diagnostics

1. Add one central error manager for contextual internal failures and queued
   user-facing messages.
2. Present pending messages only from a stable Unity main-thread flow and keep
   the shared prompt in front of other UI.
3. Protect hook callbacks, application startup, subsystem teardown, worker
   entry points, and UI action boundaries that can currently leak exceptions.
4. Include operation name, source location, exception detail, and recovery
   outcome in the private log.

### Stage 4: Confirmed reliability and responsiveness fixes

1. Make `ApplicationRoot::Stop()` complete every subsystem cleanup even when
   one subsystem fails.
2. Make completed-worker joins non-terminating and context-rich.
3. Coalesce high-frequency settings persistence generated by sliders while
   preserving immediate in-memory feedback and eventual durable settings.
4. Keep expensive AFK media decode separate from UI responsiveness where this
   can be done without moving Unity texture work off the main thread.
5. Remove stale comments or duplicated defensive layers found during the
   targeted review.

### Stage 5: Documentation and maintainability

1. Add comments that explain lifetime, threading, recovery, and ordering
   decisions rather than narrating obvious syntax.
2. Update build, dependency, troubleshooting, privacy, and support-log
   documentation for the private logger.
3. Improve the GitHub-facing repository layout and support guidance without
   claiming untested release readiness.
4. Write a post-change resolution document mapping every confirmed finding to
   its correction and validation evidence.

### Stage 6: Verification and commits

1. Re-run all host and repository invariant tests.
2. Build the Android ARM64 library and QMOD.
3. Inspect `libsaberstage.so` dynamic dependencies and exported symbols.
4. Inspect the generated QMOD manifest and archive contents.
5. Review the final diff for scope, comments, generated files, and accidental
   inclusion of local artifacts.
6. Commit in rationale-rich stages so individual changes remain reviewable.

## Completion criteria

- SaberStage can initialize and write its own current/previous log without
  Paper2.
- `libsaberstage.so` has no direct Paper2 dynamic dependency and the QMOD does
  not declare Paper2 directly.
- Dependency mods remain free to install and use Paper2.
- Confirmed hook, teardown, and worker exception paths cannot terminate the
  process through an escaping C++ exception.
- Error popups are queued and presented on the Unity main thread in front of
  active menu UI.
- Existing host/tooling tests pass, the ARM64 build succeeds, and package/ELF
  validations pass.
